## maplibre-gl-handwriting

Types from `maplibre-gl` in the declarations: `CustomLayerInterface`, `CustomRenderMethodInput`, `IControl`, `MapLibreMap` (its `Map`).

### Functions

#### createHandwriting

```ts
function createHandwriting(map: MapLibreMap, options: HandwritingOptions): Handwriting;
```

Adds a layer that draws the strokes of `options.store` to the map and turns pointer input on the map into stroke ops for the selected tool. The store is the caller's: the sync layer connects to it, not to the handle.

The tip of a stroke being drawn reaches the screen sooner on a map made with `canvasContextAttributes: { desynchronized: true }`, where the browser supports it

#### parseDefaults

```ts
function parseDefaults(value: unknown): HandwritingDefaults;
```

Checks settings the caller kept, e.g. getSettings() output saved in localStorage, before they are passed back as `defaults`: returns them when createHandwriting would take them, and throws otherwise (a TypeError when `value` is not an object, a RangeError for a field out of shape, e.g. one saved by an older version). An eraser mode 'partial' passes, as createHandwriting turns it into 'stroke' while the partial eraser is off

#### strokesToGeoJSON

```ts
function strokesToGeoJSON(strokes: Iterable<StrokeData>): string;
```

A FeatureCollection, as a JSON string, with one Feature per stroke that has points: a LineString of the stroke's sample points in WGS84 [lng, lat] rounded to 9 decimals, without the points that rounding made equal to the one before, or a Point when one is left. Features are in drawing order (strokes without an order last), then by id

### Classes

#### HandwritingLayer

```ts
class HandwritingLayer implements CustomLayerInterface {
    readonly id: string;
    readonly type = "custom";
    readonly renderingMode = "2d";
    readonly ready: Promise<void>;
    constructor(options: HandwritingLayerOptions);
    onAdd(map: MapLibreMap, gl: WebGL2RenderingContext): void;
    onRemove(): void;
    render(gl: WebGL2RenderingContext, options: CustomRenderMethodInput): void;
    destroy(): void;
}
```

A MapLibre custom layer that only draws the strokes of a store: no tools, no pointer input and no DOM. For a map that shows strokes without editing them, or to place the strokes among the style's layers yourself: `map.addLayer(new HandwritingLayer({ store, id: 'strokes' }), beforeId)`.

The WebAssembly module starts loading on the first onAdd; nothing is drawn until it has loaded, and then the map is repainted. A module or a tessellation worker that fails to load is the map's error event, `{ error, layerId }` (on the console when nothing listens for it), and the layer then draws nothing, also when added again. MapLibre calls no onRemove when it rebuilds the style (setStyle without a diff) or when the map is removed: add the layer again after such a setStyle (e.g. on style.load; a style changed by a diff keeps it), and call destroy once it is no longer wanted, which frees its worker and GPU resources whether or not it is still on the map.

A store given to both a HandwritingLayer and createHandwriting is drawn, and tessellated, twice

- `ready`: Resolves once the WebAssembly module has loaded on the main thread and in the first of the layer's tessellation workers to answer; the loading starts on the first onAdd and the worker is made by an onAdd, so it never resolves for a layer never added to a map. Rejects when either fails to load, and the layer then draws nothing. A worker that fails after it has settled (one made after a style was rebuilt) is only the map's error event. Resolves on destroy when it has not settled yet
- `destroy()`: Removes the layer from the map when it is on the map's style, and frees its worker, its store subscription and its GPU resources also when it is not (the style was rebuilt without it, or the map removed). The layer draws nothing after this, even when added again

#### HandwritingToolbar

```ts
class HandwritingToolbar implements IControl {
    constructor(handle: Handwriting);
    onAdd(map: MapLibreMap): HTMLElement;
    onRemove(): void;
}
```

A floating toolbar for a handle: the hand and the handle's tools (getTools), undo and redo, per tool a popover with its settings (press the selected tool again), and a toggle for pen-only input. It can be dragged to any side of the map and collapsed; where it is goes to the handle's settings (setToolbar), so it is saved and restored with the pens.

`map.addControl(new HandwritingToolbar(handle))`. The toolbar floats over the map wherever its placement says, whatever corner it is added to. It uses only the handle's functions and events; remove it with map.removeControl before destroying the handle. Its styles are the package's `style.css`, loaded by the user

#### LaserChannel

```ts
class LaserChannel {
    nextTrail(): number;
    emit(op: LaserOp, origin: LaserOrigin): void;
    subscribe(listener: LaserListener): () => void;
}
```

Passes laser ops from whoever draws or receives them to whoever shows or sends them, like StrokeStore does for strokes but holding nothing. Every handle and sync connection given the same channel shares its trail numbers

- `nextTrail()`: A trail number for a new line of this screen, different from the ones given before it
- `subscribe()`: Calls `listener` with every op emitted from now on. Returns the function that stops it

#### StrokeStore

```ts
class StrokeStore {
    constructor(options?: StrokeStoreOptions);
    apply(op: StrokeOp, origin: Origin): boolean;
    get(id: string): StrokeData | undefined;
    values(): IterableIterator<StrokeData>;
    subscribe(listener: StrokeListener): () => void;
}
```

Holds the list of strokes, applies ops and notifies subscribers. Both our own ops and others' ops go through apply, so the render layer does not care where an op came from. The store keeps its own copies of the points it is given. Points that are not a Float64Array of x and y in turn, and width coefficients that are not a Float32Array of one per point, are not taken: a points op or a restore with them is not applied, and a load, a reset or a replace leaves out the strokes with them

- `apply()`: Ignores ops that cannot be applied (e.g. points for an unknown ID) and returns false
- `get()`: The stroke with this ID, or undefined
- `values()`: Every stroke held. They come in no set order: the drawing order is each stroke's order
- `subscribe()`: Call the returned function to unsubscribe

### Types

#### EraserMode

```ts
type EraserMode = 'stroke' | 'partial';
```

'stroke' erases every stroke the eraser touches as a whole. 'partial' erases only the part of a stroke within reach and leaves the rest as new strokes; a stroke without an order yet is left alone

#### EraserSettings

```ts
type EraserSettings = {
    radius: number;
    mode: EraserMode;
};
```

The eraser tool's reach and mode (setEraser)

- `radius`: How far from the pointer the eraser reaches past a stroke's edge, in CSS px, 1 to 64

#### ExperimentalFeatures

```ts
type ExperimentalFeatures = {
    partialEraser?: boolean;
    predictionMs?: number;
};
```

Features still being worked on, off unless HandwritingOptions.experimental turns them on, and values still being tuned

- `partialEraser`: The partial eraser (EraserMode 'partial'), whose behavior is to be reworked. Default false
- `predictionMs`: How far ahead of each pointer input the browser's predicted points are drawn after the tip of the stroke being drawn, in ms; 0 draws none. Fixed when the handle is created. Default 20; createHandwriting throws a RangeError for a value that is not a number from 0 to 25

#### Handwriting

```ts
type Handwriting = {
    readonly ready: Promise<void>;
    setTool(tool: Tool): void;
    getTool(): Tool;
    getTools(): NonNullable<Tool>[];
    setPen(tool: PenTool, pen: Partial<Pen>): void;
    getPen(tool: PenTool): Pen;
    setPalette(colors: string[]): void;
    setEraser(eraser: Partial<EraserSettings>): void;
    setToolbar(toolbar: Partial<ToolbarSettings>): void;
    setPenOnly(enabled: boolean): void;
    getSettings(): HandwritingSettings;
    undo(): void;
    redo(): void;
    canUndo(): boolean;
    canRedo(): boolean;
    exportGeoJSON(ids?: Iterable<string>): string;
    clearHistory(): void;
    setKeyboard(enabled: boolean): void;
    isKeyboardEnabled(): boolean;
    on<K extends keyof HandwritingEventMap>(type: K, listener: HandwritingListener<K>): void;
    off<K extends keyof HandwritingEventMap>(type: K, listener: HandwritingListener<K>): void;
    destroy(): void;
};
```

What createHandwriting returns

- `ready`: Resolves once the WebAssembly module has loaded on the main thread and in the first of the layer's tessellation workers to answer. The layer is added once the module has loaded on the main thread and the style has loaded (and holds the beforeId layer), and again after each style.load that leaves it out, such as setStyle without a diff; its worker is made when it is added, so ready waits for the style and the beforeId layer too. Rejects when either module or the worker fails to load, or the worker cannot be made (a worker script of another origin, or a Content Security Policy that forbids it), which is also the map's error event, `{ error, layerId }` (on the console when nothing listens for it); the layer then draws nothing and makes no worker again, also after the style is rebuilt. A worker that fails after ready has settled is only the error event. Resolves on destroy when it has not settled yet
- `setTool()`: Throws a RangeError for a tool the handle does not offer (HandwritingOptions.tools)
- `getTools()`: The tools the handle offers, as given in HandwritingOptions.tools (without repeats); the hand is not one of them
- `setPen()`: Changes the given fields of a pen. The next stroke drawn with it uses them. Throws a RangeError for a color that is not #rrggbb; numbers are clamped to their ranges
- `setPalette()`: Replaces the palette: 5 colors, #rrggbb
- `setEraser()`: Changes the given fields of the eraser; the radius is clamped to its range. Throws a RangeError for an unknown mode, and for 'partial' unless HandwritingOptions.experimental turns the partial eraser on
- `setToolbar()`: Changes where the toolbar sits. HandwritingToolbar calls it when it is moved or collapsed; the handle only keeps the value and reports it in settingschange. Throws a RangeError for an unknown edge
- `setPenOnly()`: Turns pen-only input on or off: while it is on, touch moves the map instead of drawing or erasing (see HandwritingSettings.penOnly). Turning it on ends a touch that is drawing or erasing at that moment
- `getSettings()`: The pens, the palette, the eraser, the pressure curve, the toolbar placement, the laser color and pen-only input. To keep them, save the settings of settingschange and pass them back as HandwritingOptions.defaults, checked with parseDefaults
- `exportGeoJSON()`: The strokes with these IDs, or the selected ones when omitted, as a GeoJSON (RFC 7946) FeatureCollection string: one LineString (or Point) per stroke, in WGS84 [lng, lat], in drawing order. IDs not in the store and strokes without an order yet are skipped
- `clearHistory()`: Forgets the undo history, e.g. when a new connection can no longer undo the previous one's erases
- `setKeyboard()`: Turns the keyboard shortcuts (HandwritingOptions.keyboard) on or off. They listen on the window, so with two handles on a page, turn them on for one only
- `destroy()`: Removes the layer and every listener, and gives the map back the gestures the tools took. Also frees the layer's worker and GPU resources when the layer is no longer on the map's style, e.g. after map.remove(). Nothing is reported on the map's error event after it

#### HandwritingLayerOptions

```ts
type HandwritingLayerOptions = {
    store: StrokeStore;
    id: string;
    wasmUrl?: string | URL;
    workerUrl?: string | URL;
};
```

The options of a new HandwritingLayer: store and id are required

- `store`: The strokes to draw. The layer only reads the store: put the strokes in it with ops, e.g. a load op
- `id`: The layer's ID in the map style, other than the layerId of a handle on the same map. Required, so that it never takes createHandwriting's default 'handwriting'
- `wasmUrl`: Where to fetch the WebAssembly module from, instead of next to this script. The tessellation worker is sent the URL the main thread loads it from, so the worker script needs no module next to it
- `workerUrl`: Where to load the tessellation worker script from, instead of next to this script. It must be of the page's origin: a browser starts no worker script from another one

#### HandwritingOptions

```ts
type HandwritingOptions = {
    store: StrokeStore;
    startStroke?: () => StrokeIdentity | null;
    author?: string;
    layerId?: string;
    beforeId?: string;
    defaults?: HandwritingDefaults;
    keyboard?: boolean;
    tools?: readonly NonNullable<Tool>[];
    experimental?: ExperimentalFeatures;
    laser?: LaserChannel;
    wasmUrl?: string | URL;
    workerUrl?: string | URL;
    onExport?: ((geojson: string) => void) | null;
};
```

The options of createHandwriting: store is required

- `store`: The strokes to draw and to edit. The handle draws every stroke in it and loads nothing itself: put the strokes in the store, e.g. with a load op, or connect a sync layer to it. Its order mode decides who gives strokes their place in the drawing order
- `startStroke`: Called on every pointerdown with a drawing tool. Returns the new stroke's ID and author, or null to ignore the input. Also called for the ID of each piece the partial eraser leaves of a stroke (the piece keeps the stroke's author); null leaves that stroke uncut. When omitted, strokes get a random UUID v4 (made with crypto.getRandomValues, so also on a page that is not a secure context) and `author`
- `author`: Author of new strokes when startStroke is omitted
- `layerId`: ID of the map layer that draws the strokes. Default 'handwriting'
- `beforeId`: The layer is inserted before this layer, or on top when omitted. While the style has no layer with this ID, the layer is not put on top: it waits, and is inserted before that layer once it appears
- `defaults`: Initial pens, palette, eraser, toolbar placement, laser color and pen-only input, e.g. the settings the app saved from getSettings(). Fields left out keep the defaults: pen black 4px with pressure, highlighter yellow 50% 16px, eraser 6px in mode 'stroke', toolbar at the bottom center, laser #ff3b30, pen-only input off
- `keyboard`: Keyboard shortcuts on the page: H or 1 move map, P or 2 pen, M or 3 highlighter, E or 4 eraser, L or 5 lasso, K laser pointer, Space held to move the map, Cmd/Ctrl+Z undo, Shift+Cmd/Ctrl+Z or Ctrl+Y redo, Delete or Backspace and Cmd/Ctrl+D delete and duplicate the selection, Esc clears it, [ and ] change the pen's width or the eraser's radius, ? lists them. Ignored while typing in a form field. The keys of a tool left out of `tools` do nothing and are left to the page. Default false; see setKeyboard
- `tools`: The tools the handle offers: setTool, the keyboard shortcuts, their list and the toolbar take only these, and the hand (null) always. Their order changes nothing: the toolbar's buttons and the keys 1 to 5 stay as with every tool. Fixed when the handle is created. Default every tool; createHandwriting throws a RangeError for an unknown one
- `experimental`: Features still being worked on, off by default, and values still being tuned. `partialEraser` enables the eraser mode 'partial': while it is off, setEraser({ mode: 'partial' }) throws a RangeError, a default mode 'partial' becomes 'stroke', and the toolbar offers no mode switch. `predictionMs` is how far ahead the browser's predicted points are drawn; createHandwriting throws a RangeError for a value that is not a number from 0 to 25
- `laser`: Where the laser pointer's lines go and come from: the lines drawn with the laser tool are emitted on it as local, and every line on it is shown for a moment. Connect the sync layer to the same channel to share them. When omitted, the handle makes a channel of its own
- `wasmUrl`: Where to fetch the WebAssembly module from, instead of next to this script. The tessellation worker is sent the URL the main thread loads it from, so the worker script needs no module next to it
- `workerUrl`: Where to load the tessellation worker script from, instead of next to this script. It must be of the page's origin: a browser starts no worker script from another one
- `onExport`: What Export in the selection's bar does with the selected strokes' GeoJSON (see exportGeoJSON). When omitted, it downloads strokes.geojson; null leaves Export out of the bar

local: drawn on this screen / remote: received from elsewhere, e.g. through a sync layer

#### LaserSettings

```ts
type LaserSettings = {
    color: string;
};
```

The laser pointer's lines. Every laser line, drawn here or received through the laser channel, is drawn in this color

- `color`: #rrggbb

#### Matrix

```ts
type Matrix = [a: number, b: number, c: number, d: number, e: number, f: number];
```

\[a, b, c, d, e, f]: a point (x, y) goes to (a x + c y + e, b x + d y + f), as in DOMMatrix and canvas. Only similarities are used: a = d and c = -b, so the scale is the same in every direction

#### Origin

```ts
type Origin = 'local' | 'remote' | 'preview';
```

local: drawn on this screen / remote: received from elsewhere, e.g. through a sync layer / preview: shown on this screen only, never sent (e.g. the partial eraser's cuts while the pointer is down)

#### Pen

```ts
type Pen = {
    color: string;
    opacity: number;
    width: number;
    pressure: boolean;
};
```

Style of the strokes a pen draws. Switching pens switches all of it

- `color`: #rrggbb
- `opacity`: 0.13 to 1. Below 1 the stroke is translucent
- `width`: CSS px at the zoom the stroke is drawn at, 0.5 to 64; the width scales with the map
- `pressure`: Whether pen pressure varies the width: with a pen (pointerType 'pen'), each point's width is `width` times the coefficient the pressure curve gives (HandwritingSettings.pressure). Mouse and touch always draw at `width`

#### PenTool

```ts
type PenTool = 'pen' | 'highlighter';
```

The tools that draw strokes, each with a pen of its own

#### PieceRange

```ts
type PieceRange = {
    from: number;
    to: number;
};
```

The part of a stroke from position `from` to position `to` along its center line, where a position s = i + t lies on the segment from point i to point i + 1, a fraction t of the way

#### Point

```ts
type Point = [x: number, y: number];
```

Normalized Web Mercator coordinates (0 to 1), e.g. of a laser line or for a transform's matrix

#### PressureCurve

```ts
type PressureCurve = {
    min: number;
    gamma: number;
};
```

How pen pressure p (0 to 1) becomes a width coefficient: min + (1 - min) * p^gamma, after smoothing p over the pointer events. Shared by every pen that has pressure on

- `min`: The coefficient at no pressure, 0.05 to 1: the thinnest a line gets, as a part of the pen's width
- `gamma`: The curve's exponent, 0.2 to 5. Below 1 a light touch already draws wide

#### StrokeData

```ts
type StrokeData = {
    id: string;
    author: string;
    color: string;
    width: number;
    zoom: number;
    points: Float64Array;
    pressure?: Float32Array;
    order?: number;
};
```

A stroke, finished or still being drawn. JSON.stringify writes a typed array as an object, so an app that sends or saves strokes as JSON turns points and pressure into arrays of numbers (Array.from) and back (new Float64Array, new Float32Array)

- `points`: The center line's points in normalized Web Mercator coordinates (0 to 1), x and y in turn: x0, y0, x1, y1, … Point i is points[2i], points[2i + 1]
- `pressure`: Width coefficient at each point, 0 to 1 (one per point, half the length of points): the stroke is `width * pressure[i]` wide there. Missing for a stroke drawn without pressure, which is `width` wide everywhere
- `order`: Position in the drawing order, an integer from 1 to MAX_ORDER: later strokes are drawn over earlier ones. Missing until the stroke gets one (an order op; see StrokeOrderMode for who applies it). Only strokes with an order can be selected, transformed, cut or exported

#### StrokeIdentity

```ts
type StrokeIdentity = {
    id: string;
    author: string;
};
```

Identity of a stroke that is about to start

#### StrokeListener

```ts
type StrokeListener = (op: StrokeOp, origin: Origin) => void;
```

A subscriber of a StrokeStore (subscribe): called after each op the store applied, with the op as applied (e.g. a transform with only the IDs that changed, a load with only the strokes added, as the store's own copies) and its origin. An op the store could not apply reaches no subscriber

#### StrokeOp

```ts
type StrokeOp = {
    type: 'begin';
    id: string;
    author: string;
    color: string;
    width: number;
    zoom: number;
} | {
    type: 'points';
    id: string;
    pts: Float64Array;
    ps?: Float32Array;
} | {
    type: 'end';
    id: string;
} | {
    type: 'order';
    id: string;
    order: number;
} | {
    type: 'remove';
    id: string;
} | {
    type: 'split';
    id: string;
    pieces: StrokePiece[];
} | {
    type: 'transform';
    ids: string[];
    matrix: Matrix;
} | {
    type: 'replace';
    strokes: StrokeData[];
} | {
    type: 'restore';
    stroke: StrokeData;
} | {
    type: 'reset';
    strokes: StrokeData[];
} | {
    type: 'load';
    strokes: StrokeData[];
};
```

A change to the strokes of a StrokeStore, given to its apply and passed on to its subscribers:

- begin, points and end: a stroke being drawn, its points (x and y in turn, as in StrokeData.points, and, for a stroke drawn with pressure, their width coefficients ps), and its end
- order: the stroke's place in the drawing order, an integer from 1 to MAX_ORDER
- remove: erases a whole stroke; restore brings a removed one back (undo of an erase, redo of a stroke)
- split: the partial eraser's cut of a stroke with an order into pieces, which keep its place in the drawing order
- transform: moves, scales and rotates strokes with an order (see transformStroke)
- replace: sets strokes held here to another copy of them, e.g. a sync layer's, which wins over what was applied here
- load: adds the strokes not in the store yet, e.g. saved ones; reset replaces all the strokes

#### StrokeOrderMode

```ts
type StrokeOrderMode = 'default' | 'custom';
```

Who gives strokes their order. default: the store does. Right after a stroke's end, a stroke with points and no order gets the next value of the store's counter, which starts at 1 and never goes down, by an order op applied with the end's origin. The strokes a load or reset brings in get the next values in the order the op lists them, whatever order they held, so no order is handed out twice. custom: the store never gives an order; the caller applies order ops (e.g. a sync layer that decides one order for every client)

#### StrokePiece

```ts
type StrokePiece = PieceRange & {

};
```

A piece of a stroke with the ID it is saved under

#### StrokeStoreOptions

The options of a new StrokeStore

- `order`: Who gives strokes their order; 'default' when omitted

#### cutStroke

```ts
function cutStroke(points: Float64Array, sweeps: readonly EraserSweep[], minLength: number): PieceRange[] | null;
```

Where the eraser cuts a stroke: the parts of its center line that stay, after removing every part within `sweep.radius` of the sweep's segment, and dropping the parts shorter than `minLength`. ```ts
